# Project management

This folder holds the evidence of how the Pac-Man project was planned,
followed and checked. Fields in `[square brackets]` must be filled by the
team with real information (dates, names, decisions): they are left empty on
purpose, because they cannot be invented.

| Document | Content |
|---|---|
| [project_analysis.md](project_analysis.md) | Scope, constraints from the subject, technical choices and why |
| [timeline.md](timeline.md) | Phases, planned vs actual progress, Kanban board |
| [risk_analysis.md](risk_analysis.md) | Risks, likelihood, impact, mitigation |
| [team_organization.md](team_organization.md) | Who does what, working rules, decision log |
| [acceptance_tests.md](acceptance_tests.md) | Test plan, results, bugs found and fixed |
| [blocking_points.md](blocking_points.md) | Blocking points and conflicts, and how they were solved |

**How to keep it useful:** update the timeline and the test results at each
work session, and add a line to the decision log whenever a choice is made.
Documents written once at the end do not show a real approach.
